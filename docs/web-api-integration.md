# Velora Web — API Integration

**Status:** W1 (2026-11-25): B1, B2, B3 and B7 are done. Source of truth for what exists: the backend code in `backend/src` and its test suite (254 tests). `backend/openapi/openapi.yaml` was compared with the controllers: **all 51 implemented operations are in the file**; the only operation in the file that does not exist is `POST /products/{id}/image-upload-url` (photos need object storage). Since W1 every response produced by the backend test suite is validated against the file, including fields the file does not declare (B7).

## 1. Client architecture

```
core/api/
  schema.d.ts            generated by openapi-typescript from backend/openapi/openapi.yaml (types only)
  api.ts                 base URL from environment ('/api/v1' — same origin), typed get/post/patch/delete helpers
  envelope.ts            unwraps { data, meta }; Page<T> = { items, nextCursor, hasMore, counts? }
  api-failure.ts         normalises errors → ApiFailure (same taxonomy and codes as the mobile app)
  interceptors/
    auth.interceptor.ts        adds Authorization: Bearer <in-memory token>; on 401 refreshes once, replays
    idempotency.ts             helper: header Idempotency-Key from the caller's Submission key
    retry-safe.interceptor.ts  one retry after 1 s for GET on network error / 502 / 503 / 504
    timeout.interceptor.ts     20 s; 60 s for PDF and CSV
features/<feature>/data/<feature>.api.ts   thin typed services: one method per operation, no state
```

- **Base URL** comes from `environment.apiBaseUrl` (default `/api/v1`). The web app and the API are served from the **same origin** (Caddy serves the built web app and proxies `/api/*`), so there is no CORS configuration and cookies can be `SameSite=Strict`. In development the Angular dev server proxies `/api` to `localhost:3000`.
- **Money** is integer minor units in both directions, never floats. Formatting uses `Intl.NumberFormat` with the organization's currency code and exponent from `/auth/me`; parsing user input uses integer arithmetic only (port of the mobile `MoneyFormatter`).
- **Dates:** documents carry calendar dates (`YYYY-MM-DD`) in the organization's time zone and instants in UTC; the web app shows instants in the organization's time zone (not the browser's).
- **Cancellation:** read requests are cancelled when superseded (`httpResource`) or when the user leaves the screen. Mutations are never cancelled once sent.
- **No mock data in the app.** Component and unit tests use `HttpTestingController`; end-to-end tests run against the real API with a seeded database.

### Code generation
`openapi-typescript` turns the YAML into TypeScript types; the thin services are hand-written on top (5–15 lines each). A generated *client* was considered and rejected: the interceptors and the idempotency/error rules are app-specific, and generated clients obscure them. The generation runs in CI and fails the build if the committed types are out of date.

## 2. Authentication for browsers

The mobile app receives the refresh token in the JSON body and keeps it in the platform keystore. A browser has no equivalent: `localStorage` and `sessionStorage` are readable by any script that runs on the page, so a single XSS bug would leak a 30-day credential.

**Proposed (needs backend change B1):**

| | Mobile (unchanged) | Web |
|---|---|---|
| Sign in | `POST /auth/login` → tokens in body | `POST /auth/web/login` → access token in body; refresh token in a cookie `__Secure-velora_rt`, `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth/web` |
| Refresh | `POST /auth/refresh` with token in body | `POST /auth/web/refresh` — cookie only, no body; rotates the cookie |
| Sign out | `POST /auth/logout` | `POST /auth/web/logout` — revokes the session and clears the cookie |
| Access token | secure storage | memory only (gone on reload; the refresh cookie restores it) |

- **CSRF:** only the three `/auth/web/*` endpoints accept the cookie; everything else requires the `Authorization` header, which a cross-site form cannot set. The cookie is `SameSite=Strict`, and the three endpoints additionally require `Origin` to equal `APP_BASE_URL` and a custom header (`X-Velora-Client: web`).
- **Several tabs:** refresh tokens rotate and a reused token revokes the whole session (reuse detection). Two tabs refreshing at once would sign the user out. The web app serialises refreshes with the **Web Locks API** (`navigator.locks.request('velora-refresh')`); a tab that waited re-reads the (already rotated) cookie by simply calling refresh again, and `BroadcastChannel` tells all tabs about sign-out.
- **Session length:** same refresh lifetime as mobile (30 days) unless decided otherwise (question Q4 in `web-implementation-roadmap.md`).
- **Server-side checks stay authoritative:** every request is checked for permission and organization by the backend (row-level security in PostgreSQL); a closed session stops working immediately (since Sprint 6).
